# Manual Database Migration Plan

This document outlines the process of manually converting the MySQL database backup into Oracle-compatible SQL scripts and executing them.

**Source File:** `db/academic_center_db_full_backup.sql`
**Target Database User:** `c##dbms_project`

---

#### **Phase 1: Script Generation**

This phase involves programmatically reading the source MySQL backup file and converting it into three separate, Oracle-compatible SQL scripts.

1.  **Generate `oracle_schema.sql`:**
    *   **Action:** Convert all `CREATE TABLE` statements.
    *   **Transformations:**
        *   Translate MySQL data types to Oracle types (e.g., `INT` -> `NUMBER`, `TEXT` -> `CLOB`, `DATETIME` -> `TIMESTAMP`).
        *   Convert `AUTO_INCREMENT` to Oracle's `GENERATED BY DEFAULT AS IDENTITY`.
        *   Remove MySQL-specific syntax like backticks, `ENGINE=...`, and `COLLATE=...`.
        *   Ensure constraints (`PRIMARY KEY`, `FOREIGN KEY`) are correctly formatted.

2.  **Generate `oracle_data.sql`:**
    *   **Action:** Convert all `INSERT INTO` statements.
    *   **Transformations:**
        *   Adjust date/timestamp string formats if necessary.
        *   Handle character escaping differences (e.g., `\'` becomes `''`).
        *   Group inserts into blocks followed by a `COMMIT;` for transaction management.

3.  **Generate `oracle_triggers.sql`:**
    *   **Action:** Convert all `CREATE TRIGGER` statements.
    *   **Transformations:**
        *   Rewrite trigger syntax for Oracle's PL/SQL.
        *   Change `NEW.column` references to `:NEW.column`.
        *   Ensure proper block termination.

#### **Phase 2: Execution**

Once the scripts are generated, they will be executed against the Oracle database in the correct order.

1.  **Purge the Schema:** The `c##dbms_project` user schema will be completely emptied to ensure a clean slate.
2.  **Execute `oracle_schema.sql`:** This will build the entire table structure in the Oracle database.
3.  **Execute `oracle_data.sql`:** This will populate the newly created tables with all the records from the backup.
4.  **Execute `oracle_triggers.sql`:** This will create the application logic (triggers) within the database.

#### **Phase 3: Verification**

After execution, checks will be performed to validate the migration, such as counting rows in key tables to ensure all data was transferred.
