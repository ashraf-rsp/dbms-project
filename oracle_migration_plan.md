# MySQL to Oracle 21c XE Database Migration Plan

## 1. Introduction

This document outlines the step-by-step plan to migrate the `dbms_project` database from MySQL to Oracle 21c XE. The plan covers the migration of schema (tables, constraints), data, and logic (triggers, routines), ensuring a complete and functional transition.

## 2. Pre-Migration Phase

### 2.1. Identify the Source Data

**Crucial First Step:** We will use the existing full backup file, `db/academic_center_db_full_backup.sql`, as the definitive source for the migration. This file contains the complete schema and data, ensuring we work from a stable and complete snapshot of the database.

### 2.2. Setup Oracle Environment

1.  **Create a Dedicated User:** It is best practice to create a new user/schema in Oracle to house the migrated database objects.
    *   Connect to Oracle as a user with administrative privileges (e.g., `SYSTEM`).
    *   Execute the following SQL commands:

    ```sql
    -- Create a new user for the project
    CREATE USER dbms_project_user IDENTIFIED BY YourSecurePassword;

    -- Grant necessary permissions to the new user
    GRANT CONNECT, RESOURCE, CREATE VIEW, CREATE TRIGGER TO dbms_project_user;
    GRANT UNLIMITED TABLESPACE TO dbms_project_user;
    ```

2.  **Obtain Oracle JDBC Driver:** Download the Oracle JDBC driver (e.g., `ojdbc11.jar` for Oracle 21c) and place it in the Tomcat `lib` directory (`D:\Java\tomcat\lib\`). This is required for the application to connect to the new database.

## 3. Migration Phase: Schema & Data

**Recommendation:** The most efficient method is to use **Oracle SQL Developer**, which has a built-in Migration Workbench designed for this purpose. It can connect to both MySQL and Oracle and automate most of the conversion. The steps below outline the manual process, which is useful for verification or if the tool is not used.

### 3.1. Schema Migration (Manual Conversion)

The core of the manual migration is converting the MySQL DDL script (`temp_schema.sql`) to Oracle's SQL dialect.

#### 3.1.1. Data Type Conversion

| MySQL Type              | Oracle Equivalent                               | Notes                                                                |
| ----------------------- | ----------------------------------------------- | -------------------------------------------------------------------- |
| `INT`, `BIGINT`         | `NUMBER` or `NUMBER(p,s)`                       | `INT` can be `NUMBER(10)`, `BIGINT` can be `NUMBER(19)`                |
| `VARCHAR(n)`            | `VARCHAR2(n CHAR)`                              | Use `CHAR` semantics to avoid byte-limit issues with multi-byte chars. |
| `TEXT`, `MEDIUMTEXT`    | `CLOB`                                          | For large text objects.                                              |
| `TIMESTAMP`, `DATETIME` | `TIMESTAMP`                                     | Oracle's `DATE` type also stores time, but `TIMESTAMP` is closer.      |
| `TINYINT(1)` (Boolean)  | `NUMBER(1)`                                     | Add a `CHECK (column_name IN (0, 1))` constraint.                    |
| `DECIMAL(p,s)`          | `NUMBER(p,s)`                                   | Direct mapping.                                                      |

#### 3.1.2. Table Definition Conversion

For each `CREATE TABLE` statement:

1.  **Remove Backticks:** Remove backticks (`) around table and column names. Use double quotes (`"`) only if you need to preserve case-sensitivity, but it's better to use standard, unquoted uppercase names.
2.  **Convert `AUTO_INCREMENT`:** Replace `AUTO_INCREMENT` with `GENERATED BY DEFAULT AS IDENTITY`.

    *   **MySQL Example:**
        ```sql
        CREATE TABLE `users` (
          `UserID` int NOT NULL AUTO_INCREMENT,
          ...
          PRIMARY KEY (`UserID`)
        );
        ```
    *   **Oracle Equivalent:**
        ```sql
        CREATE TABLE USERS (
          "UserID" NUMBER(10) GENERATED BY DEFAULT AS IDENTITY,
          ...
          PRIMARY KEY ("UserID")
        );
        ```

3.  **Remove MySQL-Specific Clauses:** Delete lines containing `ENGINE=...`, `DEFAULT CHARSET=...`, and `COLLATE=...`.

#### 3.1.3. Trigger Conversion

Trigger syntax is significantly different.

*   **MySQL Example (`update_user_message_counts`):**
    ```sql
    CREATE TRIGGER `update_user_message_counts` AFTER INSERT ON `messages` FOR EACH ROW
    BEGIN
        -- ... logic using NEW.SenderUserID ...
    END
    ```
*   **Oracle Equivalent:**
    ```sql
    CREATE OR REPLACE TRIGGER UPDATE_USER_MESSAGE_COUNTS
    AFTER INSERT ON MESSAGES
    FOR EACH ROW
    BEGIN
        -- ... logic using :NEW.SenderUserID ...
    END;
    /
    ```
    **Key Differences:** Use `CREATE OR REPLACE`, reference new/old values with a colon (`:NEW`, `:OLD`), and terminate the block with `/`.

### 3.2. Data Migration

1.  **Extract Data from MySQL:** Dump only the data from MySQL into a separate file.
    ```sh
mysqldump -u dbms_user -pashraf --no-create-info --compact dbms_project > dbms_project_data.sql
    ```
2.  **Prepare Data for Oracle:** The `INSERT` statements from `mysqldump` are mostly standard. However, you may need to find-and-replace to fix potential issues with date/timestamp formats or character escaping.
3.  **Load Data into Oracle:**
    *   **Disable Constraints:** To speed up the data loading process, disable foreign key constraints before running the insert script.
    *   **Run the Script:** Use `sqlplus` or SQL Developer to execute the `dbms_project_data.sql` script.
    *   **Re-enable Constraints:** Re-enable the constraints and check for any data that violates them.

## 4. Post-Migration Phase

### 4.1. Application Configuration Update

The application cannot connect to the new database until its configuration is updated.

1.  **Edit `webapp/db_connection.jsp`:**
    *   **Comment out** the old MySQL configuration.
    *   **Add** the new Oracle configuration.

    ```jsp
    <%--
    // OLD MySQL Credentials
    String dbUrl = "jdbc:mysql://localhost:3306/dbms_project";
    String dbUser = "dbms_user";
    String dbPassword = "ashraf";
    Class.forName("com.mysql.jdbc.Driver");
    --%>

    // NEW Oracle Credentials
    String dbUrl = "jdbc:oracle:thin:@//localhost:1521/XEPDB1"; // Default for Oracle XE
    String dbUser = "dbms_project_user";
    String dbPassword = "YourSecurePassword"; // Use the password you set
    Class.forName("oracle.jdbc.driver.OracleDriver");

    Connection conn = null;
    // ... rest of the file remains the same
    ```

### 4.2. Verification and Testing

1.  **Compile Invalid Objects:** After migrating data and triggers, some objects in Oracle might be marked as invalid. Recompile them.
    ```sql
    -- Run this as the dbms_project_user
    BEGIN
      FOR i IN (SELECT object_name, object_type FROM user_objects WHERE status = 'INVALID') LOOP
        IF i.object_type = 'PACKAGE BODY' THEN
          EXECUTE IMMEDIATE 'ALTER PACKAGE ' || i.object_name || ' COMPILE BODY';
        ELSE
          EXECUTE IMMEDIATE 'ALTER ' || i.object_type || ' ' || i.object_name || ' COMPILE';
        END IF;
      END LOOP;
    END;
    /
    ```
2.  **Data Integrity Check:** Run `COUNT(*)` queries on key tables in both MySQL and Oracle to ensure all rows have been migrated.
3.  **Full Application Test:** Redeploy the web application and perform a full regression test of all features: user login, course management, enrollment, messaging, etc., to ensure the application runs correctly with the Oracle database.
